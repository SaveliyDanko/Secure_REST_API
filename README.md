# Secure REST API

Учебный REST API на Java и Spring Boot с аутентификацией по JWT и хранением данных в H2.

## Запуск

Требуются Java 21 и Maven.

```bash
APP_PASSWORD='your-password' mvn spring-boot:run
```

Приложение доступно по адресу `http://localhost:8080`. Логин по умолчанию `demo`. Его можно изменить переменной окружения `APP_USERNAME`.

H2 работает в памяти: после перезапуска записи удаляются. Ключ подписи JWT также создаётся при запуске, поэтому ранее выданные токены после перезапуска перестают действовать.

## API

| Метод | Адрес | Назначение | Доступ |
|---|---|---|---|
| POST | `/auth/login` | Получить JWT | Без токена |
| GET | `/api/data` | Получить записи | С токеном |
| POST | `/api/data` | Добавить запись | С токеном |

### Получение токена

```bash
curl -X POST http://localhost:8080/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"demo","password":"your-password"}'
```

Ответ содержит поле `token`. При неверных учётных данных сервер возвращает `401 Unauthorized`.

### Получение записей

```bash
curl http://localhost:8080/api/data \
  -H "Authorization: Bearer ВСТАВЬТЕ_JWT"
```

### Добавление записи

```bash
curl -X POST http://localhost:8080/api/data \
  -H "Authorization: Bearer ВСТАВЬТЕ_JWT" \
  -H "Content-Type: application/json" \
  -d '{"text":"Новая запись"}'
```

При успешном добавлении сервер возвращает `201 Created`. Без действительного токена защищённые эндпоинты возвращают `401 Unauthorized`.

## Меры защиты

### Защита от SQL-инъекций

Поиск пользователя и начальное заполнение базы выполняются через `JdbcTemplate` с фиксированным текстом SQL и параметрами `?`. Значения логина, хэша пароля и записи передаются отдельно от SQL-запроса, поэтому пользовательский ввод не может изменить его структуру. Для добавления записей используется `SimpleJdbcInsert` с параметром `text`. SQL-запросы не собираются конкатенацией строк с пользовательскими данными.

### Защита от XSS

Текст записи хранится в H2 в исходном виде, а перед возвратом из `GET /api/data` и `POST /api/data` экранируется функцией `HtmlUtils.htmlEscape`. Например, введённое `<script>alert(1)</script>` возвращается как `&lt;script&gt;alert(1)&lt;/script&gt;`. API отдаёт данные в JSON, а поле `text` обязательно и ограничено 500 символами.

### Аутентификация и контроль доступа

Пароль начального пользователя передаётся через `APP_PASSWORD`. При запуске `BCryptPasswordEncoder` создаёт его хэш, который сохраняется в H2 вместо открытого пароля. При входе сервер ищет пользователя по логину и проверяет пароль через `PasswordEncoder.matches`; неверный логин или пароль приводит к ответу `401 Unauthorized`.

После успешного входа сервер выдаёт JWT с логином пользователя в `sub`, временем выпуска `iat` и сроком действия `exp` через один час. Токен подписывается алгоритмом HS256 ключом из 32 случайных байт, который генерируется при запуске. Spring Security проверяет подпись и срок действия токена из заголовка `Authorization: Bearer <token>` на защищённых запросах. Без токена доступен только `/auth/login`; остальные маршруты требуют аутентификации. Сервер не создаёт HTTP-сессию, а после перезапуска новый ключ делает ранее выданные токены недействительными.
